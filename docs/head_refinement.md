# 在 Acc 约束下微调细分类别

这是已有模型的第二阶段训练。默认运行 5 轮，冻结特征提取、解码器和一级分类头，只训练二级及更深层级的条件分类头。支持现有的二至四级结构、部分标签、混合像元和不同深度的叶类；单级分类没有可微调的下级头，会明确报错。

## 运行

先完成普通训练，再用同一数据集及原实验的模型、数据配置启动新实验：

```powershell
uv run python scripts/train.py data/processed/<原数据集时间戳> `
  --config experiments/<原实验时间戳>/model.yaml `
  --data-config experiments/<原实验时间戳>/data.yaml `
  --train-config configs/train.yaml `
  --init-checkpoint experiments/<原实验时间戳>/model_<原实验时间戳>.pt `
  --refine-heads --device cuda:0
```

当前阶段支持单卡或 CPU。它会创建新实验，不覆盖原实验。原实验旁必须保留 `train_log.json` 和 `spatial_split.json`，以核对数据划分。如果原训练曾使用 `--window-size`、`--stride`、`--halo`、`--grid-offset`、`--region-fraction` 等覆盖参数，微调时也应传入相同值。数据路径迁移后需先更正配置中的路径。

类别结构、类别含义及输入特征必须与初始权重一致。若更新标签后重新生成了不同的分类层级或空间划分，应先按新数据正常训练，再微调新模型；旧实验权重不能直接套用。初始模型或当前配置若把测试集并入训练，会拒绝运行。

微调参数位于 `configs/train.yaml` 的 `head_refinement` 段；默认 `enabled: false`，命令行 `--refine-heads` 开启。也可以设置 `enabled: true`，但仍须提供初始权重。`--epochs` 可覆盖本次微调轮数。

中断后使用新实验的完整断点恢复，原有基准和最佳候选会一并恢复：

```powershell
uv run python scripts/train.py data/processed/<原数据集时间戳> `
  --resume experiments/<微调实验时间戳>/last.pt --device cuda:0
```

## 训练和模型筛选规则

- 每个训练像素每轮先作为监督锚点一次。仅对标签明确的少数叶类补采样，补充次数总量不超过训练像素数的 25%，每个像素每轮最多三次（含首次）。混合、部分标签像素保留一次访问；不会因包含多个观测标签而变成多个锚点。采样只使用训练标签频数。
- 默认学习率为 `3e-5`。关闭伪标签、类别损失加权和 EMA，避免叠加过强的类别补偿。继续使用现有层级监督、数据增强、halo 和重叠一致性约束；读取仍是按窗口进行，不缓存全区域特征。
- 微调前，在相同验证窗口上重新评估初始权重，记录固定基准。即使普通训练以一级指标选模型，本阶段也按**标签明确的叶类**选择模型；没有这类验证标签时会停止，不能用混合标签一致度替代 Acc。
- 候选的叶类验证 Acc 必须不低于“初始 Acc − 0.005”，即最多下降 **0.5 个百分点**。这个下限始终相对初始模型，不随上一轮结果逐步放宽。
- 通过 Acc 下限后，依次比较：有验证样本但零召回的类别数更少、macro-F1 更高、在有真实样本的类别上 macro-precision 更高、Acc 更高。没有验证样本的类别不计入零召回数。精确相同时保留已有候选。
- 初始权重也是候选。没有更优且达标的候选时，最终 `model_*.pt` 保留初始权重，`best_epoch` 为 0。此阶段不输出其他不受 Acc 约束的 `best_*.pt`；`last.pt` 只用于续训，不应用作最终测试权重。

这里统计的是混淆矩阵中真正的零，而非小数位显示为零。在有真实样本的类别上，召回率为零意味着 TP 为零，对应精确率也为零。macro-F1 延续项目已有的真实或预测出现类别口径；额外的 macro-precision 使用有真实样本的类别口径。

## 诊断结果和正式测试

新实验包含 `training_baseline.json`、`validation_baseline.json`，以及每轮的 `training_epoch_*.json`、`validation_epoch_*.json`。训练诊断不使用数据增强，按原来的独立像素合并窗口概率，记录逐类混淆矩阵、支持数、预测数、精确率和召回率；混合标签仍单独记录。`train_log.json` 的 `head_refinement` 保存基准、Acc 下限、最终最佳指标和可训练参数列表，各轮记录是否达标、是否被选中。诊断会增加一次训练集前向评估的耗时。

训练完成后，照常对新实验的 `model_*.pt` 运行 `scripts/test.py` 和 `scripts/predict.py`。没有加入类别概率重加权，也没有改变测试指标定义、出图判定规则、类别编码或图例；新权重学到的预测本身可能改变。

**0.5 个百分点是验证集上的筛选限制，不是独立测试集的保证。** 测试集不参与调参或挑选。该方法无法保证消除零准召率，尤其不能保证修复特征不可分、标签不足或错误大类概率主导的类别；实际改进需要训练后在独立测试集上检验。
